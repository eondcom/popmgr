## 여는 글

이 책은 코드에 대한 책이 아니다. **요청법에 대한 책이다.**

소재는 popmgr 다. Pop!_OS(COSMIC) 노트북에서 흩어져 있던 관리 작업 — 한글 입력기, 트랙볼, 오디오, 디스크, 밝기, 전원 — 을 한 창에 모은 Rust 데스크톱 앱이다. 이 책은 그 앱의 하루, 2026년 9월 24일 하루치 기록이다.

하루 동안 보낸 말은 **23건, 2,086자**였다. 그중 두 건은 붙여 넣은 스레드 초안이라 실제로 쓴 말은 훨씬 짧다. 그런데 그 하루에 이런 일이 있었다.

| 결과 | 불러낸 말 |
|---|---|
| 배터리 2%에서 꺼지던 원인을 찾아 5%에서 먼저 절전하는 기능을 만들었다. 같은 날 밤 9%에서 실제로 절전해 작업을 살렸다 | "배터리 얼마 없으면 5% 정도라던지 하면 자동절전모드로 가는 방법" |
| 로그인할 때마다 한글 입력기가 두 개 떠서 서로 싸우던 것을 찾았다 | "창 왔다갔다한다거나 특정한 상황일때 한글이 … 영어로만 쳐지는 현상" |
| 절전 복귀 훅이 두 달 동안 **한 번도** 동작하지 않았다는 것을 찾았다 | "energe safe mode->hangull not working" |
| 디자인 시스템을 색만 따라 했다는 것을 인정하고 글꼴·라운딩·버튼까지 맞췄다 | "그냥 컬러만 좀 참고한 느낌인데" |
| 저장소 버전을 로컬 캐시로만 말했던 것을 서버에 직접 물어 다시 확인했다 | "Pop!_OS 저장소 찾아보고말하는거야?" |

오른쪽 열의 말은 모두 짧다. 몇몇은 오타가 섞였고 하나는 영어다. 그래도 통했다. 이 책은 **왜 통했는지**를 따라간다. 그리고 통하지 않은 말 — 같은 요청을 두 번 보내야 했던 경우 — 도 나란히 놓는다.

### 다른 권 안내

「프롬프트 사용법」은 소재만 바꿔 같은 질문을 되풀이하는 시리즈다. 1권은 영상 자동편집(eondcut), 2권은 NAS 파일관리 프로그램, 3권은 8TB 나스 정리가 소재다. 어느 권부터 읽어도 된다. 여러 권에 같은 교훈이 반복해서 나온다면, 그건 소재가 달라도 같은 요청법이 통했다는 근거다.

## 1장 만든 것

popmgr 는 탭 열 개짜리 관리 앱이다. 이 책의 하루 동안 다섯 가지를 고치거나 새로 만들었다.

| # | 무엇 | 한 줄 요약 |
|---|---|---|
| 1 | 배터리 부족 시 자동 절전 | 배터리로 쓰는 중 5% 이하면 강제 종료 전에 절전. 깨어난 뒤 3분은 다시 잠들지 않는다 |
| 2 | 한글 입력 풀림 | 입력기 중복 실행 끄기, 절전 복귀 훅 v3, 설치 불가능한 경고 제거 |
| 3 | 세 손가락 제스처 | 컴포지터를 패치해 재빌드하던 방식을 버리고 작은 사용자 서비스로 |
| 4 | 파일 탐색기 경로 복사 | 업그레이드로 지워진 패치를 안전하게 다시 적용할 수 있게 |
| 5 | 디자인 정합 | ui.eond.com/app 디자인 시스템의 글꼴·버튼·카드·라운딩·글자 크기 |

진행 상황은 구글 시트에 이슈별로 남겼다. 첫 요청의 마지막 문장이 그걸 정했다.

> "task 등록, 구글 sheep api 활용해서 eond all project management 시트에 popmgr 탭. 태스트 등록해서 해당 항목 처리 이슈 상태 남겨가면서 처리해보자"

"sheep" 는 sheet 의 오타고 "태스트" 는 task 다. 그래도 시트 이름, 탭 이름, 기록할 내용(이슈 상태)이 다 들어 있어서 한 번에 됐다. 이 한 줄 덕분에 하루 내내 "지금 뭐가 어디까지 됐나"를 시트 한 장으로 볼 수 있었다. 원인이 확인되면 비고 칸에 원인을, 구현하면 커밋 해시를, 실기로 확인하면 "실기확인"을 적었다.

## 2장 어떻게 쓰는가

### 배터리 자동 절전 — 전원 탭

전원 탭 맨 아래 카드 **"배터리 부족 시 자동 절전"** 에서 쓴다.

| 조작 | 동작 |
|---|---|
| 입력칸에 % 입력(1~30, 비우면 5) | 이 값 이하에서 절전 |
| **켜기 (pkexec)** | 관리자 비밀번호를 한 번 묻고 시스템 타이머를 설치 |
| **임계값 적용** | 값을 바꿔 다시 설치 |
| **끄기** | 타이머와 파일을 전부 제거 |
| **지금 점검** | 절전하지 않고 "지금 조건이면 어떻게 될지"만 보여 준다 |

켜 두면 **popmgr 를 닫아도, 재부팅해도** 동작한다. 이 점은 사용자가 먼저 물었다.

> "배터리 8% 였는데 이거 왜 그 감지해서 못했나. 프로그램 실행중이 아니어서 그랬나 항상 실행은 안되나"

답은 둘이었다. 그 시점엔 아직 '켜기'를 누르지 않았고, 켰더라도 기본값 5%라 8%에서는 동작하지 않는다. 그리고 앱은 켜고 끄는 화면일 뿐, 실제 감시는 root 타이머가 한다. 이 질문이 좋았던 이유는 **가설을 같이 말했기 때문**이다("프로그램 실행중이 아니어서 그랬나"). 가설이 있으니 답이 가설을 확인하거나 반박하는 형태로 바로 나왔다.

동작 기록은 저널로 본다.

```bash
journalctl -t popmgr-battery-guard      # "battery 9% <= 10% -> suspend"
journalctl -u popmgr-battery-guard      # 1분마다 OK / SKIP 판정
```

### 한글 — IME 탭

| 카드 | 언제 뜨나 | 버튼 |
|---|---|---|
| fcitx5 가 두 번 실행됨 | 자동실행과 systemd 유닛이 둘 다 fcitx5 를 띄울 때 | 중복 끄기(다음 로그인부터) |
| 절전 복귀 IME 자동 복구 | 훅이 없거나 구버전일 때 | 훅 설치 (pkexec) |
| 툴킷 프론트엔드 미설치 | 그 툴킷 앱이 실제로 있는데 모듈이 없을 때만 | 설치 |
| IME 재시작 | 항상 | 입력기만 다시 띄움 |

### 세 손가락 제스처와 경로 복사 — COSMIC 탭

세 손가락은 '켜기' 한 번이면 된다. root 도 재빌드도 필요 없다. 예전 방식의 컴포지터 패치가 남아 있으면 카드가 먼저 그걸 지우라고 안내한다. 둘이 같이 있으면 오버뷰가 열렸다 바로 닫히기 때문이다.

경로 복사는 패치 없이도 이미 된다. **Shift+우클릭 → '복사 경로'**, 또는 **Ctrl+Shift+C**. 패치는 Shift 없이도 메뉴에 보이게 하는 것뿐이다.

### 설치

popmgr 는 바이너리를 복사해 설치하는 구조라, 소스를 고쳐도 다시 빌드해 넣기 전에는 반영되지 않는다.

```bash
cargo build --release
cp target/release/popmgr ~/.local/bin/popmgr.new && mv -f ~/.local/bin/popmgr.new ~/.local/bin/popmgr
```

실행 중인 파일을 `cp` 로 덮으면 "Text file busy" 가 날 수 있어서, 새 이름으로 복사한 뒤 이름을 바꾼다.

## 3장 어떻게 동작하는가

### 배터리 가드

```
1분마다 root 타이머 → 가드 스크립트
  배터리(주변기기 제외) 없음        → SKIP
  AC 연결 / 충전 중                → SKIP
  잔량 > 임계값                    → OK
  깨어난 지 3분 안                 → SKIP (유예)
  그 외                            → systemd suspend -i
```

`-i` 는 절전 방지(inhibit)를 무시하라는 뜻이다. 여기서 안 자면 곧 UPower 가 전원을 끈다. 절전 방지보다 데이터가 먼저다.

유예는 복귀 훅이 깨어난 시각을 적어 두는 방식이다. 유예가 없으면 5%에서 깨어난 뒤 1분 만에 다시 잠든다. 저장할 틈도, 충전기를 꽂을 틈도 없다.

### 한글: 왜 창마다 달랐나

로그인할 때 fcitx5 를 띄우는 곳이 **두 군데**였다. systemd 유닛 하나, `/etc/xdg/autostart` 항목 하나. 둘이 거의 동시에 떠서 Wayland 입력 연결을 두고 경쟁한다. COSMIC 은 좌석당 입력기 연결을 하나만 주고, fcitx5 는 거절당하면 다시 시도하지 않는다. 순서가 꼬이면 **살아남은 쪽이 Wayland 연결이 없는 채로** 세션 내내 돈다.

그러면 Wayland 앱(COSMIC 앱, Chrome, Electron)만 영문이 되고, GTK 앱이나 카카오톡(XIM)은 멀쩡하다. 그래서 "창마다 다르다"로 보였다. 최근 부팅 4번 중 3번이 이 순서였다.

해결은 `~/.config/autostart` 에 같은 이름의 파일을 `Hidden=true` 로 두는 것이다. XDG 규칙상 사용자 폴더의 같은 이름 파일이 시스템 항목을 덮는다. root 가 필요 없다.

### 세 손가락

COSMIC 컴포지터는 세 손가락 제스처를 받기만 하고 아무 일도 하지 않는다(업스트림 코드에 TODO 로 남아 있다). 그래서 따로 읽어도 겹치지 않는다. 서비스는 터치패드 이벤트를 읽어 **스와이프 전체의 누적 이동량**이 위쪽이면 오버뷰를 연다. 예전 패치는 첫 프레임 한 번의 움직임으로 방향을 정해서, 살짝 대각선으로 시작하면 제스처 전체가 무시됐다.

## 4장 요청법 — 무엇이 통했나

### 증상과 원하는 결과를 한 문장에

> "배터리 모드일때 배터리 얼마 없을 때 자동으로 종료되더라. 그러면 작업중이던 임시데이터가 날라가버림. 그래서 그걸 막기 위해서 배터리 모드면 배터리 얼마 없으면 5% 정도라던지 하면 자동절전모드로 가는 방법 만들어볼까. popmgr에 넣어보자."

이 한 문장에 네 가지가 다 있다. 무슨 일이 일어나나(자동 종료), 무엇이 손해인가(임시 데이터), 원하는 동작(절전), 기준값(5% 정도), 넣을 곳(popmgr).

"5% 정도라던지" 가 특히 컸다. 숫자가 있으니 AI 는 "지금은 몇 %에서 무슨 일이 일어나나"부터 확인했고, 설정 파일에서 `PercentageAction=2`, `CriticalPowerAction=HybridSleep` 을 찾았다. 그리고 이 PC 는 디스크 스왑이 없어(zram 만 있음) 하이브리드 절전을 할 수 없으니 **전원 끄기로 폴백**한다는 원인이 나왔다. 증상만 말했으면 "절전 기능을 만들어 드릴게요"로 끝났을 것이다. 기준값을 말했기 때문에 현재값과 비교가 시작됐다.

### 근거의 출처를 되묻는다

> "upower 업데이트하면 해결되는 문제는 아닌가"

AI 는 "Pop!_OS 저장소에는 1.90.3 뿐이라 apt 로는 못 올린다"고 답했다. 맞는 답이었지만 근거가 로컬 apt 캐시였다.

> "Pop!_OS 저장소 찾아보고말하는거야?"

이 한 줄로 AI 는 **로컬 캐시만 봤다고 인정**하고, 저장소 서버 다섯 곳(release, noble, updates, security, backports)의 패키지 목록을 직접 받아 대조했다. 결론은 같았다. 하지만 이번엔 근거가 달랐다.

교훈은 이렇다. **AI 의 "없다"는 어디를 보고 한 말인지 물어볼 가치가 있다.** 이 질문은 AI 를 의심하는 게 아니라 근거의 층위를 올리는 일이다. 대답이 같아도, 두 번째 대답은 남에게 그대로 전할 수 있다.

### 막연한 느낌을 구체적인 항목 하나로 짚는다

> "popmgr 디자인이 ui.eond.com/app을 참고한거 맞니? 라운딩이라던지. 그냥 컬러만 좀 참고한 느낌인데"

"디자인이 좀 다르다"였으면 AI 는 이것저것 손봤을 것이다. 여기엔 **기준(ui.eond.com/app)**, **의심 항목(라운딩)**, **가설(색만 따라 했다)** 이 다 있다.

AI 는 가설을 그대로 검증했다. 디자인 토큰 크레이트에 라운딩·버튼 높이·글자 크기 토큰이 다 있는데 popmgr 가 쓰는 곳은 **0곳**이었고, 라운딩은 일곱 가지 값이 하드코딩돼 있었다. 표 한 장으로 "맞게 보셨습니다"가 나왔다. 조사 중에 기본 글꼴이 NanumSquare **Bold** 라 본문까지 전부 굵게 나온다는 것도 드러났다.

> "응 진행해, 시트에 #5로 등록하고"

승인과 기록 위치를 한 문장에 줬다. 1장의 첫 요청과 같은 형태다. 작업을 시키는 문장에 "어디에 남길지"를 붙이면 따로 챙길 일이 없다.

### 조건 → 증상, 화살표 하나

> "energe safe mode->hangull not working"

오타 두 개, 영어, 여섯 단어. 그런데 이 말이 이날 가장 깊은 버그를 찾았다.

화살표가 핵심이다. "한글이 안 된다"만 있었으면 앞서 고친 중복 실행 문제로 돌아갔을 것이다. **"절전 → 한글 안 됨"** 이라는 순서가 있으니 AI 는 절전 기록부터 봤고, 거기서 두 가지가 나왔다.

- 22:15:11 배터리 가드가 9%에서 **실제로** 절전시켰다(가드 첫 실전).
- 22:15:52 깨어났는데 복귀 훅은 아무 일도 하지 않았다.

그 훅은 두 달 전(7월 20일)에 "v2" 로 고쳐 둔 것이었다. 알고 보니 v2 는 **한 번도** 동작하지 않았다. 훅에서 띄운 프로세스가 절전 서비스와 같은 묶음(cgroup)에 들어 있어서, 훅이 끝나는 순간 systemd 가 묶음째 정리한다. 5장에서 자세히 본다.

교훈: **증상 앞에 조건을 붙인다.** 화살표 하나면 충분하다. 문법도 철자도 상관없다.

### 누른 것과 본 것을 같이 말한다

> "툴킷은 미설치됨 설치눌러도"

여섯 글자짜리 보고지만 정보가 둘이다. 한 행동(설치를 눌렀다)과 본 결과(여전히 미설치). 이게 있으니 AI 는 "설치 명령이 실행은 됐나"부터 봤고, 저널에서 22:18 한 분 사이에 세 번 실행된 기록을 찾았다. 설치가 실패하고 있었다.

### 이미 있는 것을 가리킨다

스레드 글을 "직접 올려 보라"는 말에 AI 는 브라우저를 열어 글을 치기 시작했다. 게시 버튼을 누르기 직전에 이 말이 왔다.

AI 는 찾아보지 않았다. 찾아보니 게시 스크립트가 있었고, 그 스크립트를 거치지 않고 올리면 **대기열 기록·하루 상한·대시보드에서 빠진다**는 경고가 문서에 적혀 있었다. 브라우저 작업을 멈추고 스크립트로 올렸다. 브라우저에선 해시태그 세 개가 토픽 하나로 뭉치는 사고도 이미 나 있었다.

두 번째 비슷한 장면에서는 AI 가 헤맸다. 사용자는 이렇게 짚었다.

> "공용에 이제 sns-publish 스킬 있어 참고해서"

## 5장 막혔다가 풀린 곳

### 배터리 2%에서 그냥 꺼지는 이유

| 확인한 것 | 값 |
|---|---|
| `CriticalPowerAction` | HybridSleep |
| `PercentageAction` | 2 |
| 스왑 | zram 16G 뿐, 디스크 스왑 없음, `resume=` 없음 |
| UPower 버전 | 1.90.3 (upowerd 안에 Suspend 선택지가 없음) |

하이브리드 절전도 최대 절전도 디스크 스왑이 필요하다. 없으면 UPower 는 **말없이 전원 끄기로 넘어간다.** 설정 파일만 바꿔서는 못 고친다. `Suspend` 는 1.90.9 이상에서 `AllowRiskyCriticalPowerAction=true` 와 함께만 된다. Pop!_OS 저장소에는 1.90.3 뿐이다(4장).

그래서 UPower 앞에서 먼저 움직이는 가드를 만들었다. UPower 의 2% 전원 끄기는 최후 안전망으로 그대로 둔다.

### systemd-sleep 훅에서 띄운 프로세스가 사라진다

v2 훅은 이렇게 생겼었다.

```sh
runuser -u "$user" -- sh -c "setsid sh -c 'sleep 1; fcitx5 -d --replace' &"
```

`setsid` 로 세션을 떼어냈으니 살아남을 것 같지만, **cgroup 은 그대로다.** `systemd-suspend.service` 는 oneshot 이고 KillMode 가 control-group 이라, 훅이 반환하는 순간 묶음 안에 남은 프로세스에 SIGTERM 을 보낸다. `sleep 1` 도중에 죽는다. 흔적도 없다(stderr 를 버렸으니까).

v3 는 사용자 systemd 매니저에게 넘긴다.

```sh
runuser -u "$user" -- env XDG_RUNTIME_DIR="$d" DBUS_SESSION_BUS_ADDRESS="unix:path=$d/bus" \
  systemd-run --user --collect --on-active=2 -p KillMode=process /bin/sh -c "$cmd"
```

`KillMode=process` 까지 줘야 한다. transient 서비스도 기본은 묶음째 정리라, 데몬화한 자식이 같이 죽는다. 이건 가짜 데몬(`setsid sleep 37 &`)을 띄워 서비스가 끝난 뒤에도 살아 있는지 실측해서 확인했다.

### 입력기 두 개가 서로를 지운다

3장에서 본 대로다. 확인은 이렇게 한다.

```bash
journalctl --user -b _COMM=fcitx5 | grep -E 'waylandim|dbus name'   # pid 두 개가 보이면 이중 기동
busctl --user call org.fcitx.Fcitx5 /controller org.fcitx.Fcitx.Controller1 DebugInfo
                                                   # frontend:wayland_v2 가 없으면 Wayland 연결 상실
```

열흘 전(9월 13일)에 "창을 옮기면 영문이 된다"를 입력 상태 공유 설정으로 고쳤었다. 그 설정은 지금도 맞게 들어가 있었다. 증상이 비슷하다고 같은 원인은 아니었다.

### 설치 버튼이 안 먹는 이유

```
fcitx5-frontend-qt6 : 의존: qt6-base-abi (= 6.4.2)
libqt6core6t64 6.8.3 설치됨   ← 다른 릴리스(plucky)에서 들어온 잔재
libqt6gui6t64   설치 안 됨     ← Qt GUI 앱이 없다
```

다른 릴리스 소스를 잠깐 섞으면 이런 잔재가 남는다. 서로만 참조하는 고아 패키지라 지워도 되지만, 지우는 것은 사용자가 확인한 뒤로 미뤘다.

### 사용자 화면에 창을 띄우지 않고 GUI 를 확인하기

디자인을 바꾼 뒤 "보여 주기"가 필요했다. 규칙상 사용자 화면에 창을 띄우지 않는다. 가상 X 화면을 썼다.

```sh
Xvfb :99 -screen 0 900x760x24 &
env -u WAYLAND_DISPLAY DISPLAY=:99 XDG_RUNTIME_DIR=<임시폴더> popmgr &
sleep 6; DISPLAY=:99 import -window root out.png
DISPLAY=:99 xdotool mousemove 90 410 click 1      # 사이드바 탭 이동
```

한 번은 캡처가 새까맣게 나왔다. popmgr 는 한 번에 하나만 실행되도록 `XDG_RUNTIME_DIR/popmgr.lock` 을 잡는데, 그사이 사용자가 popmgr 를 켜 둬서 캡처용 인스턴스가 바로 종료된 것이다. 캡처할 때만 `XDG_RUNTIME_DIR` 을 임시 폴더로 바꿔 해결했다.
